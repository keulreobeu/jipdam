## 1. 수집 전에 검색·예약

1. 전체 기록에서 **출처 + 데이터 종류 + 지역 코드/영역 + 조회 기간**을 검색한다. 닫힌 Issue·부분 완료·업로드 대기·예약도 확인한다.
2. 같은 출처의 서울 전체/종로구, 1~12월/9월은 범위가 겹친다. 이미 성공한 범위와 다른 담당자가 예약·진행 중인 범위는 제외하고 **미수집/실패분만** 예약한다. 시설은 종류·검색 영역·기준일을 비교한다. 결과를 바꾸는 필터/쿼리도 함께 기록한다.
3. `[수집] 출처 | 종류 | 지역 | 기간` 제목으로 Issue를 만들고 담당자와 예정 범위를 적는다. 예약 후 다시 검색해 겹치는 동시 예약이 있으면 담당자를 정한 뒤 시작한다.

성공한 0건은 수집 완료다. 실패/미조회는 0건이 아니다. 일부 페이지만 받았다면 요청 전체 완료로 쓰지 않는다. 새 기준 시각의 갱신 수집은 이전 Issue와 이유를 연결한다. 같은 원본을 CSV/SQLite로 변환하는 작업은 새 수집 예약 없이 기존 기록에 추가한다. **합성 예시는 실제 수집 범위를 차지하지 않는다.**

## 2. 짧은 필수 기록

배치당 Issue 하나를 갱신한다. 장문의 로그 대신 각 항목 1~2줄로 적는다. 지역·월별 성공 목록이 길면 ZIP의 manifest를 가리키고 요약에는 끝난 범위와 남은 범위를 쓴다.

```text
출처·종류: 공식 서비스/URL · 아파트 전월세
범위·담당: 지역코드 11110 · 계약월 202509~202512 · @담당자
상태·결과: 부분 완료 · 9~11월 전체 페이지 완료(10월 0건), 12월 실패 · 총 N건
방법·품질: 지역×월×페이지 XML, 보증금/월세 만원→원, 단지 매칭 미검수 · 실제/원천 미검수
중복 확인: 기존 #번호의 완료/예약 범위 제외 · 재조회라면 기준 시각과 이유
파일·해시: 배치명.zip · SHA-256 64자리 · manifest.json · 조회 시각 ISO-8601
Drive: 업로드 전 '업로드 대기'; 업로드 후 개별 ZIP 링크
```

위 수치·범위는 양식 예시이며 수집 실적이 아니다. 예약 시 상태는 `예약`, 결과는 `미수집`, ZIP/해시는 `미생성`, 링크는 `업로드 대기`로 쓴다. 수집 후에는 실제 성공/빈 응답/실패 범위·건수·가공 방법·검수 상태로 갱신한다. 조회 기간과 수집일을 구분하고, 모르는 원천 날짜·취소/정정 상태는 `미확인`으로 쓴다.

## 3. ZIP 업로드 전후

- 업로드 **전**: Issue 결과 갱신 → ZIP 내부 `manifest.json` 포함 → 최종 ZIP SHA-256 기록 → 같은 해시의 기존 배치 검색. 동일 해시는 기존 링크를 사용한다.
- 파일명: `출처_종류_지역_조회기간_수집일_배치ID.zip`. 합성은 `synthetic_` 접두어로 구분한다. 파일명만으로 중복 여부를 판정하지 않는다.
- manifest 최소 항목: `batch_id`, `source`/서비스 URL, `dataset`, `quality_status`, 요청 범위/필터, `retrieved_at_utc`, 성공/0건/실패 요청과 페이지 현황, 행 수, 원본 파일별 SHA-256, 단위/가공 규칙, 검수 상태/누락. ZIP 외부 해시는 완성 후 Issue에 적어 자기 참조를 피한다.
- 업로드 **후**: Issue에 개별 ZIP의 Drive 링크를 추가하고 `업로드 완료`로 갱신한다. 폴더 링크만으로 개별 파일의 업로드 완료를 표시하지 않는다.
- 첨부 합성 ZIP은 원본 DB만 포함하고 내부 manifest가 없으므로 현재 첫 기록에 그 누락을 남긴다. 보존 원본을 변경하거나 실제 수집 완료로 승격하지 않는다.
- API 키·개인정보·원본/DB/ZIP은 GitHub에 올리지 않는다. Git에는 요약·링크·해시·운영 문서만 남긴다.

공통 AGENTS는 기록 누락 시 수집/업로드를 진행하지 않도록 요구한다. [GitHub Issue Form](https://docs.github.com/en/communities/using-templates-to-encourage-useful-issues-and-pull-requests/syntax-for-githubs-form-schema)은 양식 제출 시 필수 항목 누락을 막는다. API를 통한 Issue 생성, 동시 예약, 사람이 직접 하는 Drive 업로드까지 자동 차단하는 기능은 아니다. API로 기록하는 AI도 같은 항목을 채워야 한다. 실제 수집/매칭의 별도 보류는 유지한다.
