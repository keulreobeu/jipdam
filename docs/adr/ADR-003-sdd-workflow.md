# ADR-003 — 저장소 문서와 기본 CI로 SDD 운영

Status: Accepted (2026-10-01). 근거: 사용자 D1~D8 선택과 구현 요청.

## Context

Spec·ADR·Task와 테스트는 있으나 요구·AC·검증 연결과 완료·병합 통제가 부족했다. 팀은 Codex·Claude Code·Antigravity를 사용한다.

## Decision

기존 문서 위치를 유지하고 운영 문서와 네 템플릿을 분리한다. 저장소 Task를 작업 상태의 기준으로 삼고 TOML 메타데이터·JSON 추적 원장을 Python 표준 라이브러리로 검사한다. 운영 체계와 평가 기능 하나부터 적용한다.

제품 요구는 사용자, 세부 구현과 증거 기반 완료는 담당자가 책임진다. 코드·계약·설정 변경은 Task를 요구하고 단순 설명은 면제한다. main은 CI 필수·사람 리뷰 권장으로 운영한다.

## Alternatives

전체 기능의 동시 전환은 첫 도입 범위를 키운다. Issue를 기준으로 삼으면 오프라인 checkout과 CI에 별도 원격 연결이 필요하다. Markdown만 파싱해 테스트를 추적하면 본문 형식 변화에 취약하다. 외부 프레임워크 도입은 현재 문서와 설치 계약을 늘린다.

## Consequences

ID·참조를 원장과 문서에서 유지해야 한다. 자동 검사는 의미적 승인이나 테스트의 충분성을 대신하지 않는다. 기존 문서는 baseline으로 관리하며 실제 평가 완료를 소급하지 않는다. gstack 결과는 초안이며 다른 AI 도구의 네이티브 스킬 지원을 새로 가정하지 않는다.
