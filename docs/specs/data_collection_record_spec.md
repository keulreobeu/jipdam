## 범위

GitHub에는 짧은 수집 기록, 지정 Drive 폴더에는 원본 ZIP을 보관한다. 수집 전 예약과 업로드 전 기록은 모든 담당자·AI 도구의 필수 절차다. 이번 요청은 수집 재개·새 API 호출·Drive 업로드·자동 수집기 변경을 승인하지 않는다.

## COLLECT-001-REQ-01 짧고 필수인 기록

데이터 배치마다 GitHub 수집 Issue 하나를 만든다. 같은 Issue를 예약→수집 중→부분 완료/수집 완료→업로드 완료로 갱신한다. 소스 URL/서비스·데이터 종류·지역 코드/시설 범위·조회 기간·담당자·진행 상태·방법/단위/가공·성공/빈 응답/실패 범위·건수·검수/합성 구분·ZIP SHA-256·Drive 파일 링크를 기록한다. 예약 시 결과와 ZIP은 `미수집`/`미생성`, 업로드 전 링크는 `업로드 대기`로 명시한다. 상태 확인을 생략한 빈 값을 완료로 취급하지 않는다.

### COLLECT-001-AC-01 필수 입력과 간결한 요약

GitHub Issue Form의 기록 항목은 필수 입력이며 예시와 같은 짧은 기록으로 무엇을 어디서 어디까지 어떻게 수집했는지 파악할 수 있다. README에서 기록·새 Issue 진입점을 찾을 수 있다.

## COLLECT-001-REQ-02 수집 전 중복 확인과 예약

완료·부분 완료·업로드 대기·진행 중·예약 및 닫힌 Issue도 검색한다. 겹침 기준은 출처/서비스 + 데이터 종류 + 조회 지역/영역 + 조회 기간이다. 쿼리·주택 종류·필터·기준일 등 결과를 바꾸는 조건도 비교한다. 서울 전체는 구별 범위와 겹치며 기간은 교집합을 확인한다. 같은 데이터의 JSON/CSV/SQLite 변환은 새 수집으로 세지 않는다.

성공한 요청 범위와 진행/예약 범위는 건너뛰고 미수집·실패 요청만 수집 대상으로 잡는다. 성공한 0건 응답과 실패/미조회는 구분한다. 부분 페이지 수집은 해당 요청 완료가 아니며 완료 페이지와 누락 페이지를 기록한다. 최신 상태 재조회가 필요하면 이전 Issue·재조회 이유·새 기준 시각을 남긴다. 서로 다른 실제 계약을 값/해시로 합치지 않는다. 예약 후 다시 검색해 동시 예약이 겹치면 담당자를 정하고 시작한다.

### COLLECT-001-AC-02 겹침·부분 완료·합성 구분

운영 문서가 전체/부분 지역·기간의 겹침, 성공 0건, 실패, 페이지 누락, 갱신 재조회, 동시 예약을 다룬다. 합성 예시는 실제 전월세 수집을 완료/예약한 범위로 취급하지 않는다. 현재 첨부의 실제 수집 범위를 추정하지 않는다.

## COLLECT-001-REQ-03 업로드 전 기록과 원본 분리

GitHub 기록과 ZIP 내부 `manifest.json`이 같은 배치·범위·건수·기준 시각을 가리켜야 한다. ZIP에 포함될 manifest는 ZIP의 외부 SHA-256을 자기 안에 넣지 않고 원본 파일별 해시를 담는다. 최종 ZIP을 만든 뒤 SHA-256을 GitHub에 기록하고 같은 해시가 있으면 다시 업로드하지 않는다. ZIP 업로드 후 개별 Drive 파일 링크를 Issue에 추가한다. API 키·개인정보·원본 데이터·DB를 Git에 넣지 않는다.

### COLLECT-001-AC-03 업로드 순서와 적용 한계

공유 폴더·manifest 최소 항목·업로드 전 기록·업로드 후 개별 파일 링크와 해시 중복 확인이 명시된다. 루트/제품 AGENTS가 이 절차를 필수로 연결한다. Issue Form은 양식 제출의 누락을 막지만 API Issue 생성·동시 예약·수동 Drive 업로드를 기술적으로 차단하지는 않는다는 한계를 명시한다.
