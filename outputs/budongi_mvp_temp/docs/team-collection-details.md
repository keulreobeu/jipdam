# 집담 3인 데이터 수집 — 상세 분담 및 제출 안내

작성일: 2026-10-13. [채팅 공유용 요약](team-collection-chat-summary.md), [확정 공통 스키마](team-data-contract.md), [TEAM-DATA-001](specs/16_team_collection_schema_spec.md).

이 파일은 사용자가 제공한 3인 분담안과 현재 DB 계약을 팀원이 읽기 쉽게 풀어 쓴 설명 자료다. 담당별 목록은 수집 준비 업무와 확장 후보를 구분한다. 신규 수집 실행·범위·사용권·실제 매칭을 승인하거나 현재 MVP에 모든 확장 기능을 추가하는 문서가 아니다. 실제 사람 이름과 신규 수집 지역/기간은 수집 예약 시 정한다.

출처 링크는 공식 카탈로그 또는 기관 진입점이다. 2026-10-13 카탈로그에서 확인한 형태와 첨부안의 확보 후보를 구분했다. 인증키를 사용한 API 성공, 실제 파일의 모든 열·좌표 품질·최신성은 아직 확인하지 않았다. 파일/API 중 실제 사용할 경로와 매핑은 샘플 검수 후 확정한다.

위 규모는 [2026-10-13 실제 점검](team-data-contract-validation-20261013.md#db-inspection)의 값이다. 기존 전월세 관측은 확정 단지 연결이 없고 canonical 후보 관계 271,299개는 모두 pending/unverified다. 기존 자료가 있다는 사실을 실제 추천·단지 매칭 완료로 해석하지 않는다.

HUG 카탈로그는 최근 3개월 평균 사고현황을 안내한다. 그 기간을 원문과 함께 보존하고 일반 월별 개별 계약 통계로 바꾸지 않는다. 사고율의 모집단·분모·정의를 확인하기 전 다른 분모로 재계산하거나 특정 계약의 사기 확률로 표시하지 않는다. [공식 카탈로그](https://www.data.go.kr/data/15134221/fileData.do).

공시가격 CSV 카탈로그는 건축물대장 연계키 제공과 일부 NULL을 안내한다. **키가 제공되면 보존하되**, 실제 식별 범위·건축HUB PK 변환·동/호실 계층을 샘플로 확인한 후 관계를 검수한다. 지금 단계에서 자동 단지 매칭을 확정하지 않는다. [공식 CSV 설명](https://www.data.go.kr/data/3073746/fileData.do).

2번의 완료물: 위치/영역 원본 + 시설/노선/관측/레이어의 분리 정규화 + 실제 제공 범위/갱신일 + 좌표/분류 오류 보고. 커버리지·중복시설·침수 판정·교통 접근성 계산은 검수 후 별도다.

## 4. 3번 — 건축물·단지 특성·보행·주거 조건

### 우선 준비할 데이터

| 데이터 | 확보 위치 | 유형·형태 | 보존할 핵심 내용 | 제출 종류·현재 연결 |
|---|---|---|---|---|
| 건축물대장 | [국토부 건축HUB](https://www.data.go.kr/data/15134735/openapi.do) | 건물·전유부 속성 / JSON·XML API | 원천 PK·계층·사용승인일·층수·구조·면적 종류·주소 성분 | building_profile/unit_profile. PK 전환 규칙 검수 필요 |

| 보행 네트워크 | [Geofabrik 한국 OSM 원본](https://download.geofabrik.de/asia/south-korea.html) | 공간 네트워크 / PBF·GPKG | 노드/구간 ID·연결·방향·접근 태그·geometry·추출 버전 | network_segment. 경로/시간 계산은 후속 |
| 반려동물 허용·제한 | 실제 관리규약·관리사무소 확인 | 조건·근거 / 문서·수작업 | 적용 단지·허용/조건부/불허/미확인·조건·검증일·검수자·근거 | restriction_evidence. 전국 공개 표준 자료가 있다고 가정하지 않음 |

건축HUB 공식 카탈로그는 종전 건축데이터의 PK가 변경돼 전환 규칙을 제공한다고 안내한다. 기존 PK·새 PK·서비스 namespace·변환근거를 보존하고 이름으로 대체하지 않는다. [건축HUB 설명](https://www.data.go.kr/data/15134735/openapi.do).

K-apt XLSX는 추출 자료이고 API와 기준시점이 다를 수 있다. 원본 파일의 추출/기준일을 보존하며 전체 서울 아파트 커버리지를 추정하지 않는다. [K-apt 파일 카탈로그](https://www.data.go.kr/data/15073271/fileData.do).

3번은 통합 식별자 등록과 충돌 보고를 맡는다. 그러나 다른 파트의 원본 수집·정규화·오류 검수까지 대신하지 않는다. 공식 외부 ID를 보존하고, 실제 같은 단지/건물이라는 관계 확정은 증거를 갖춘 후속 검수에서 한다.

## 5. 각자 통일해야 할 DB/스키마 규칙

아래는 확정 계약의 요약이다. 전체 필드/필수성/타입은 [팀 데이터 계약 §2~7](team-data-contract.md)을 따른다. 이 설명 파일이 새 스키마 버전을 만들지는 않는다.

| 항목 | 공통 규칙 |
|---|---|
| 내부 ID | complex_id/building_id/address_id는 통합 경로에서 발급·재사용. 미연결 NULL 허용 |
| 공식 외부 ID | namespace + source_entity_id + entity_level + 근거. 서로 다른 출처의 같은 숫자를 합치지 않음 |
| 행정코드 | 코드는 TEXT. sgg_cd 5자리, 전체 bjd_cd 10자리, 현행 addresses.legal_dong_code는 뒤 5자리 |
| 주소 | 도로명·지번 원문 각각 보존. 불완전 성분으로 주소 ID 생성 금지 |
| 좌표 | 제공 원좌표/CRS/축 순서 보존. 표준 latitude/longitude는 WGS84. 결측은 두 열 모두 NULL, 검수 상태 별도 |
| 단위 | 거래 금액 원 정수 / 면적 ㎡ / 거리 m. 통계는 원단위·Decimal 정밀도를 유지 |
| 결측 | NULL과 실제 0/false를 구분. 없는 정보를 채우지 않음 |
| 날짜 | 계약일·기준일·기간·공표일·수집시각·적재시각 분리. 미확인 NULL |
| 원본 추적 | source_id + 파일 참조/해시 + section + 행/셀/feature 위치 보존 |
| 버전/중복 | batch_id·mapping_version·입력 서명 추적. 같은 입력 재실행 신규 0, 개정본은 과거값 보존 |
| 데이터 종류 | 거래·통계·시설·건물·실시간 관측·공간·규약 분리. 현행 거래 importer는 rental/sale만 지원 |
| 상태 | 수집 완료와 사실 검수/관계 확정/추천 적격성은 별도 |

좌표/날짜/단위를 새 출처에 실제 적용하는 매핑과 신규 도메인 적재기는 후속이다. 원본 계층·키·형식을 유지하면 기존 DB와 새 자료를 연결할 근거를 잃지 않는다.

## 6. 파일 제출 위치와 구성

각 제출 묶음의 계약상 구조는 `<source_id>/<batch_id>/`다. 로컬 보관 위치 예시는 제품 폴더의 `data/collection/team/<source_id>/<batch_id>/`이며 기존 MOLIT·통계 경로를 이 위치로 이동할 필요는 없다. 원본·DB·ZIP은 Git에 넣지 않는다. 공유 Drive 업로드는 별도 승인·기록 절차 후 진행한다.

```text
<source_id>/<batch_id>/
  raw/                         # 받은 원본 그대로
  normalized/<record_type>.jsonl
  schema.json                  # 열/타입/단위/NULL/원필드 매핑
  manifest.json                # 출처·범위·시간·파일 hash/건수
  validation.json              # 대사·결측·중복·오류·미확정 관계
  README.md                    # 재현/오프라인 파싱 방법
  code/                        # 코드 또는 저장소 commit/모듈 참조
```

JSONL은 공통 제출 형태다. 현재 stage-file이 지원하는 일반 JSON(items_path)/CSV/XLSX와 구분한다. 기존 거래 importer에 넣기 위한 변환은 원본과 별도 파일로 만들고 그 계보를 남긴다. 지원하지 않는 새 종류는 보존 제출하고 적재 완료로 표시하지 않는다.

제출 체크리스트:

- [ ] 기존 완료·예약 Issue와 지역/기간/필터 중복을 확인했다.
- [ ] 신규 수집 승인·담당·출처·범위를 예약했고 동시 예약을 재확인했다.
- [ ] 원본 bytes를 수정 없이 보존하고 파일별 SHA-256을 기록했다.
- [ ] 출처 URL·라이선스 원문/링크·기준일·실제 수집시각을 기록했다. 미확인은 NULL/pending이다.
- [ ] 정규화 컬럼의 타입/단위/결측/원필드 매핑·버전을 남겼다.
- [ ] 원본 수 = accepted + excluded + rejected를 대사했다. 통계 accepted에는 numeric+missing이 포함된다.
- [ ] 성공 0건·부분·실패·미수집을 구분했다.
- [ ] 오류 위치/사유·중복·결측·코드/좌표 충돌·미확정 관계를 보고했다.
- [ ] 재현 코드/명령과 실행 버전 또는 저장소 commit을 남겼다.
- [ ] ZIP 공유 전 같은 Issue에 실제 결과·manifest·최종 ZIP 해시를 기록했다.
- [ ] 업로드 승인·실행 후에는 같은 Issue에 개별 파일 링크를 추가했다.

수집 예약과 ZIP 결과 양식은 [수집 현황·절차](../../../docs/data-collection.md)를 사용한다. 성공한 기존 범위는 제외하고 실패/미수집 또는 명시적 갱신 범위만 다룬다.

## 7. 수집 후 결정할 내역

| 후속 판단 | 주 담당 | 확인할 증거 | 그 전 처리 |
|---|---|---|---|
| 실제 API 태그·파일 layout/단위 | 각 담당 | 공식 설명 + 실제 샘플 + 전 페이지/시트 대사 | raw 보존·미매핑·provisional |
| K-apt·MOLIT·건축HUB 실제 관계 | 3번 + 각 원천 담당 | ID 체계·PK 전환·주소 성분·불일치 검수 | 엔터티 분리·FK NULL·pending 후보 |
| 좌표 대표점·변환·오차 | 2번 시설 + 3번 단지 | CRS/축·점의 의미·지도/샘플 검수 | 원좌표 보존·표준 좌표 NULL/pending |
| 시설 중복·분류·전체 커버리지 | 시설 담당 | 원천 ID/업종·운영기관·범위/경계·갱신일 | 별개 관측·coverage unknown/partial |
| HUG 비율·통계 지역 관계 | 1번 | 모집단/집계기간/분모·지역문맥·공식 코드 | 원통계 보존·계산/지역 연결 보류 |
| 공시가격의 실제 평가대상 연결 | 1번 + 3번 | 전유부/건물/단지 계층·연계키·기준일 | 독립 평가액, 거래와 분리 |
| 침수 분석·보행 경로 | 2번 공간 + 3번 보행 | 분석 가능 자료/사용조건·해상도·네트워크 연결/누락 | 판정/경로시간 계산 보류 |
| 규약·관리비·에너지 의미 | 3번 | 실제 문서·검수자/확인일·대상/기간/단위 | unknown/원문·미확인 NULL |
| 추천/위험지표·가중치 | 통합 담당 + 사용자 | 검수된 관계/좌표/커버리지 + 제품 요구 | 수집/적재와 별도 후속 작업 |

신규 공통 시범 지역·기간은 아직 선정하지 않았다. 기존 데이터는 서울 중심으로 재사용한다. 등기/개별 권리관계·실제 매물의 호실/가격·보증 가입 가능 여부·개별 계약 판단은 별도 접근·자료·제품 계약이 필요하며 이번 대량 공공데이터 분담에 포함하지 않는다.
