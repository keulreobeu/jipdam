# 1~5번 후속 작업 목적과 실행 순서

승인 근거: 2026-10-14 사용자의 “5까지 진행할 수 있도록 하고 각 파트별로 목적 설정해서 진행”. 후속 요청은 난이도에 따라 GMS 6.1 SOL 또는 6.0 LUNA 사용을 포함한다. 검수 패키지와 로컬 모델은 사용자가 “미준비”로 답했다.

| 파트 | 목적 | 실행·완료 증거 |
|---|---|---|
| 1 DB 경로 | 중간 DB 정리 뒤에도 첫 실행·serving 재생성이 동작하도록 한다 | 보존된 canonical v3를 기본 입력으로 사용; 원본 해시 보존; 실제 prepare와 readiness 확인 |
| 2 검수 입력 준비 | 승인된 패키지가 들어오면 자동 확정 없이 실제 추천을 시작할 수 있도록 한다 | 패키지 계약·경로·원본 해시·추천 적격성을 확인하는 준비 검사와 명령; 실제 자료는 미준비 유지 |
| 3 모델·성능 준비 | 지정 로컬 모델과 실제 후보의 질문/추천/상세 검증을 재현 가능하게 한다 | 로컬 모델 미지정 게이트와 벤치마크 명령; 실제 성공 지연·실모델 성공은 자료 제공 후 검증 |
| 4 Drive 다운로드 | 공유 원본을 새 환경에서 필요할 때 검증하며 받을 수 있도록 한다 | 통계 및 MOLIT 실제 다운로드·조각/전체 해시·기존 출력 보호; 외부 장애와 합성 검증 구분 |
| 5 문서·Git 정리 | 구현 상태와 Task를 일치시키고 검증된 코드만 공유 가능하게 한다 | 이전 웹/데이터 Task에 최신 구현 연결; SDD·전체 회귀·비밀/원본 제외 검사; 로컬 Git 제출 정리 |

GMS 공통 목적: 단순·기계적 작업에는 gpt-6-luna, 구조·보안·복합 변경에는 gpt-6.1-sol을 사용한다. 정확한 ID·GMS 요율·모델별 입력 카운트·최대 예약·실계정 차감 대사를 적용한다. 실제 잔액·만료·활성/불확정 hold는 보호한다. 수집/매칭·추천용 로컬 모델·키 보관 경계는 유지한다.

실제 데이터 패키지 또는 로컬 모델을 임의 생성하지 않는다. 자료 준비와 실제 제품 완료는 별도로 보고한다. 실행 증거는 [후속 검증](../continuation-validation-20261014.md), 작업은 [Task](../tasks/continuation-parts-1to5.md)로 추적한다.

최신 예산 지시: 현재 mode는 reserve_only, 고정 보존액은 0크레딧이다. 잔액 전액을 작업에 쓸 수 있으며 활성/불확정 hold와 호출 최대비용 예약은 보존한다. 누적 비용/토큰은 원장에 기록하고 실행 한도로 적용하지 않으며, 호출별 기술 토큰 상한·사전 카운트·잔액/만료 검사는 유지한다. 과거 5,000/1,000 보존 지시는 이력이다. 실제 검수 자료와 추천용 로컬 모델 준비는 별도 게이트다.


2026-10-15 GMS 우선 사용: 사용자는 남은 크레딧을 활용해 가능한 코드·테스트·기계적 문서 작업을 최대한 GMS로 진행하도록 지시했다. 명확한 Task/AC/범위로 작업을 묶어 단순 초안은 LUNA, 구조·보안·복합 검토는 SOL을 우선 호출하고 로컬 담당자가 검토·적용·검증한다. 현재 reserve_only의 고정 보존액은 0이며 활성/불확정 hold와 최대 예약·기술·만료·비밀 경계는 유지하고 호출 횟수 자체를 목표로 삼지 않는다.
