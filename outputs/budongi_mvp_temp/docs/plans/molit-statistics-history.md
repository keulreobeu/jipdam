# MOLIT 거래량 통계 기간 정합 수집 계획

사용자 승인일: 2026-10-15. 기준 통계는 제공 통계의 `주택매매거래량(거래량)-3년` 및 아파트 거래량 자료가 공유하는 월 범위 `2024-01~2026-08`이다. 지역은 기존 제품/수집 범위와 같이 서울25구다.

## 범위와 재사용

- 대상: MOLIT 아파트 전월세, 매매 일반, 매매 상세 API 원본 XML.
- 목표: 계약일 2024-01-01~2026-08-31, query 월 202401~202608, 25구×32개월×3서비스=2,400 query.
- 기존 Issue #5 / 검증된 ZIP에서 202510~202608의 825 query를 hash 검증 후 재사용한다.
- 202401~202509의 21개월×25구×3서비스=1,575 query만 Issue #7에 예약하고 새로 조회한다.
- 기존 배치에는 202610 query가 있으나 통계 목표 범위에는 포함하지 않는다. 원본은 보존한다.
- 매매 일반/상세는 별도 원천 관측이다. 중복 제거된 계약 건수라고 합산하지 않는다.

## 절차

1. Issue #7 예약 상태를 확인한다. 범위 충돌이 없음을 확인한 상태다.
2. 새 batch plan을 `snapshot_date=2026-08-31`, `observation_from=2024-01-01`, `months=202401..202608`, `record_url=Issue #7`로 생성한다.
3. 검증된 기존 archive를 cache로 지정해 완료된 202510~202608 query를 재사용한다. 서비스/구/월/페이지 크기/해시가 일치하는 것만 허용한다.
4. 명시된 자격증명 ID를 CRED-001에서 서비스별로 지정하고 누락 페이지만 순차 수집한다. 인증/일일 quota 오류면 해당 서비스를 중단한다.
5. 2,400개 query 전체 완료 후 status·원본 행 대사·오프라인 DB 재생성·pack/ZIP SHA를 확인한다. 파일/키는 Git에 넣지 않는다.
6. 실제 범위별 성공·0건·실패·행수·조회시각·manifest·최종 ZIP SHA를 Issue #7에 적고, Drive 업로드는 별도 승인 범위가 이미 유효한 경우에만 수동 절차로 한다.

## 완료 조건

- 2,400/2,400 query가 complete 또는 complete_zero이며 실패·미조회가 0.
- 검증된 원본 825 query 재사용과 신규 fetch query 범위를 manifest/status가 구분한다.
- 관측 DB 계약일이 2024-01-01~2026-08-31로 제한되고 staging 원본 행 수 = valid + outside_period + rejected, 거부 0, DB/원본 조인이 일치한다.
- DB/ZIP은 새 출력 경로에 생성하며 이전 DB/XML/ZIP을 덮어쓰지 않는다.
- 실제 수집은 `source_unverified`로 유지하고 단지 매칭·좌표·시설·추천에 연결하지 않는다.
