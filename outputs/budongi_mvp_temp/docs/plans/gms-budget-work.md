# PLAN-GMS-BUDGET-001 — 잔액·토큰 한도 안에서 GMS 코드 작업

담당자: keulreobeu. 날짜: 2026-10-14. 사용자 요청: 실제 잔여량 조회, 사용자가 설정한 토큰만 사용, 매번 입력/출력 예상 비용 계산, 계획과 Goal 설정, 잔액이 있으면 명확한 코드 작성 작업에 GMS 사용. [Spec](../specs/18_gms_budget_spec.md), [ADR](../adr/ADR-011-gms-budgeted-work.md), [Task](../tasks/gms-budget-work.md).

## 실행 순서

1. 제공 GMS 가이드의 `GET https://gms.ssafy.io/gmsapi/key-info`를 서버에서 호출해 totalCredit/usedCredit/remainCredit/expiredDate(KST)를 표시한다. 예상 시간 계산 UI를 잔액/한도 관리로 교체한다.
2. 키 ID·최소 보존 크레딧·전체 사용 크레딧/토큰 한도·호출당 입력/출력 한도·예상 출력량·호출당 비용 한도를 저장한다. 초기 실행은 비활성이고 사용자 설정을 요구한다. 저장은 무통신이다.
3. 모든 생성 전에 잔액/만료를 조회하고 전체 입력을 GMS 경유 Responses input_tokens로 센다. 이 조회에도 관측상 크레딧이 붙어 조회 비용(현재 상한 20)부터 예약/잔액 차이로 정산한다. 출력 예상량은 사용자 설정/해당 작업값으로 계산한다. 최대 출력 비용까지 예약해 초과를 막는다. 카운트 API가 미지원이면 생성하지 않는다.
4. 승인된 작업을 하나의 고정 요청으로 동결한다. 예산·키·설정·유효기간을 다시 확인하고 사전 카운트를 재사용해 한 번 생성한다. usage 요율 비용/계정 전후 차감 중 큰 값으로 보수적으로 정산하고 사용량 없는 실패는 최대 비용을 보류한다. 재시도는 명시적인 새 견적이다.
5. `gms-work` CLI는 범위가 명확한 코드 작업의 목표/AC/선택 코드 파일만 보내고 코드 초안을 반환한다. 모델에 파일 수정·셸·DB·Git 권한을 주지 않는다. 담당자가 적용/테스트한다. 앞으로 해당 작업은 잔액과 정책이 허용하면 이 경로를 우선 사용한다.
6. 합성 HTTP/원장/동시성/재시작/오류 테스트와 실제 잔액 조회·브라우저 한도 흐름을 검증한다. 유료 생성은 사용자 설정과 명시 실행 요청 뒤에만 한다.

## 확정 경계와 미결정

현재 Codex 채팅 자체의 모델 공급자를 바꾸는 도구는 제공되지 않았다. 전체 Codex CLI를 GMS에 직접 연결하면 도구 반복 호출의 입력/출력을 이 예산 장치가 통제하기 어려우므로 이 단계에서는 제한된 작업 runner를 사용한다. GMS는 키와 코드 문맥을 지정된 API로만 받는다. 원본 DB/원시 데이터/다른 자격증명/로그를 문맥으로 읽지 않는다.

출력은 정확한 사전 예측이 불가능하다. 예상 비용과 최대 비용을 함께 표시하고 최대 비용으로 예약한다. 실제 GMS 잔액은 팀의 다른 사용에도 변하므로 앱 내 한도와 계정 전체 잔액을 구분한다. 사용자 후속 지시로 현재 작업에서 GMS 사용과 최소 5,000크레딧 보존을 확정했다. 구현 담당자가 보수적인 전체 500크레딧/10,000토큰, 호출당 입력 4,000/최대 출력 2,000/예상 출력 1,000토큰/280크레딧 초기 한도를 적용했다. 웹에서 변경 가능하며 이를 사용자가 직접 지정한 숫자라고 소급하지 않는다. 실제 key-info와 input_tokens 경유 조회는 성공했다. 최종 유료 작업 결과는 Task에 기록한다.

Goal: 이 계획의 잔액·예산·견적·정산·코드 작업 경로 구현/검증. 문서/합성 AC 완료, 실제 key-info 성공, 유료 코드 작업 성공을 각각 기록한다.
