# ADR-006 — 배치 소속과 출처 ID 근거를 구분하는 통합 DB

Status: Accepted. 2026-10-13 사용자 후속 통합 계획 승인. CANONICAL-001/TASK-CANONICAL-001 관련.

2026-10-13 구현 근거 보완: CSV/JSON/XLSX 하나에 여러 지역·계약월이 들어갈 수 있으므로 canonical_real_estate_v3에서 batch_files의 파일 단위 지역·월을 NULL로 허용한다. 행의 지역·계약일과 coverage의 지역·월 그룹은 유지한다. 파일 전체/선택 섹션의 기대 건수를 검증하며, 제공기관의 별도 지역·월 총수가 없으면 coverage.expected_rows는 NULL로 명시한다. v2 입력은 해시·무결성을 확인한 뒤 새 출력 사본의 batch_files만 변환한다. 기존 스냅샷의 수정·파괴적 마이그레이션은 없다. 테이블 수와 나머지 행 값은 유지하며 전체 digest 대사로 검증한다.

파일 원본의 JSON 선택 경로는 해시 디렉터리와 원래 JSON pointer 섹션으로 구분한다. 같은 선택의 새 매핑 버전은 기존 원본 행을 재사용한다. 파일 스테이징 v4는 기존 v3를 자동 덮어쓰지 않으며 새 출력에서 재생성한다. 신규 배치로 얻은 엔터티 지식은 신규 배치 후보에 적용하고, 이미 게시된 배치를 재실행할 때 과거 후보를 추가하거나 바꾸지 않는다. 실제·합성 품질 영역의 DB를 서로 합치지 않는다.

기존XML와전월세/매매DB를보존하며새canonical출력을만든다. SQLite와기존정규화/검증을재사용하고파일입력은source_files,관계형적재는collection_integrate,CLI는collection_cli책임으로유지한다. 하나의큰수집/매칭모듈과새ORM/DB서버도입은확장이나검증부담을늘려채택하지않는다.

원본콘텐츠와배치소속을분리한다. 같은콘텐츠의다른배치조회는배치이력을유지하고,동일배치/버전/입력재실행은신규0이다. 정정/버전은원천의명시적근거없이는자동동일거래로연결하지않는다. 불변snapshot출력과명시적배치적재를사용하여기존출력수정/실패부분게시를방지한다.

단지/건물/주소/행정구역공통엔터티와출처ID매핑을정의한다. 확인된공식출처ID의namespace/범위를유지하고이름/주소문자열유사성은pending후보로만보관한다. 원천식별근거가없는건물/주소는연결하지않는다. 라벨조인용증거를엔터티별로요약하여거래행간대규모조인을피하되원본근거는관계표로추적한다.

정규화typed필드를관계형컬럼/제약으로보관하고전체원문은staging의JSON으로보존한다. 모든자료를EAV만으로저장하면타입/단위/FK검증과실제조회가약해지므로채택하지않는다. 새로운등록출처는원본/매핑/목표record type계약으로추가하며기존파이프라인전체를재작성하지않는다.

현재입력/manifest검증은pack과integrate가공유한다. 재수집없이원본복원경로를검증하여사용하고기존ACL/역사DB를수정하지않는다. 실제추천/좌표/시설과새출처수집/Drive업로드는여전히범위밖이다.
