# ADR-011 — GMS의 잔액과 최대 비용 예약

Status: Accepted. 날짜: 2026-10-14. [Spec](../specs/18_gms_budget_spec.md), [Plan](../plans/gms-budget-work.md), [Task](../tasks/gms-budget-work.md).

사용자 요청에 따라 가정 시간 대신 공식 key-info 실잔액을 표시한다. 단순 잔액 양수만으로 작업을 실행하면 나중에 쓸 크레딧을 소진할 수 있어 보존 크레딧과 전체/호출당 비용·토큰 한도를 모두 검사한다. 예상 출력 비용만 예약하면 실제 출력 증가를 막지 못하므로 최대 출력 비용을 SQLite에서 원자적으로 예약한다. usage 불명확 실패는 보수적으로 최대 비용/토큰 보류를 유지한다.

초기 실행을 비활성으로 두고 사용자가 한도를 설정한다. 명확한 작업의 요청만 동결해 GMS로 보내며 결과는 로컬 검토 대상이다. 전체 Codex CLI 공급자 직접 전환은 도구 반복 요청의 비용을 이 정책이 통제하지 못하므로 채택하지 않는다. 현재 채팅의 모델 교체 도구도 제공되지 않았다. 제한된 runner를 통해 GMS로 코드 초안을 작성하고 담당자가 적용/검증한다.

프롬프트·코드·키는 원장에 저장하지 않고 견적의 짧은 유효기간 동안 서버 메모리에만 둔다. 앱 외의 팀 사용은 로컬 정책이 통제할 수 없으므로 생성 전 공식 잔액을 다시 조회한다. 실제 usage 기반 비용은 제공 요율 계산이며 계정 전체 잔액과 구분한다. 공급자가 한도를 지키지 않으면 다음 호출을 막고 위반을 표시한다.
