# ADR-008 — 기존 DB를 보존하고 팀 제출 계약을 먼저 통일한다

Status: Accepted. 2026-10-13 사용자 스키마 확정 요청. TEAM-DATA-001 / TASK-TEAM-DATA-001.

현재 canonical v3는 거래의 raw/배치/typed 관측/공식 출처 ID와 pending 후보를 보존한다. 통계는 statistics_v1 별도 DB에 Decimal·시리즈·기간/셀 위치를 저장한다. rental_v1은 합성 추천 경로와 수집 관측 경로에 존재하지만 실제 추천 매칭·시설을 갖추지 못했다.

선택: 기존 열/ID/원본을 유지하고 `team_collection_v1` 제출 계약의 공통 계보 + 종류별 typed 필드 사전을 확정한다. 기존 rental/sale 파일 어댑터는 재사용한다. 새 종류는 정규화 파일로 먼저 보관하고 실제 샘플 검수 뒤 별도 어댑터/추가 스키마 Task로 연결한다. `complex_id`는 통합 경로가 기존 값을 재사용하며 각자가 생성하지 않는다. 공식 외부 ID는 namespace와 함께 수집한다. 서로 다른 출처 엔터티 간 alias/관계 테이블의 실제 연결과 물리적 확장은 후속이다.

이유: 모든 자료에 단지 FK를 필수로 요구하면 수집 전 매칭을 강요하고, HUG 지역 통계·노선·공간레이어를 단지 사실로 오인한다. 단지/건물/호실 계층을 분리하고 NULL/미확정 관계를 허용하면 실제 수집자가 원본과 식별 근거를 잃지 않는다. 현행 addresses.legal_dong_code는 전체 10자리 코드가 아닌 뒤 5자리 성분이므로 교환의 bjd_cd와 명시적으로 매핑한다.

대안: 기존 complexes를 바로 전 출처 단일 마스터로 재작성하면 봉인 DB/해시/관측 FK의 호환성을 깨고 아직 없는 매칭 근거를 요구한다. 모든 신규 값을 observations.normalized_payload_json에 넣으면 typed 제약과 도메인 의미를 약화한다. 새 DB 서버/ORM 도입은 이번 제출 계약 확정에 필요 없다.

결과: 세 담당은 원본/정규화/스키마/manifest/품질 보고를 같은 구조로 제출한다. 기존 DB도 계약 안에서 그대로 재사용한다. 자료 제출과 적재 지원, 적재와 검수, 검수와 추천을 별도로 완료 처리한다. 이번 결정은 신규 원격 수집·실제 매칭·마이그레이션의 승인이나 구현 완료가 아니다.
