# ADR-025 — 기존 앱 안의 독립 분석 파이프라인

Status: Accepted. 2026-10-29 사용자 구현 승인. PIPELINE-001 / KAN-28.

기존 budongi 내부 pipeline 패키지와 CLI에 분석 경로를 추가한다. 기존 canonical/통계/추천 DB를 마이그레이션하지 않고 등록된 오프라인 입력에서 새 결과를 게시한다. 원본 식별/배치/위치와 논리 데이터셋을 구분하고 66개 목록을 66개 고유 거래 집합으로 해석하지 않는다.

Python이 파일 파싱·단위·NULL·원본 계보를, dbt가 후속 사실/차원/마트를 책임진다. 같은 정규화 규칙을 두 엔진에 중복 구현하는 ELT 전환과 단계별 서비스 분할은 기존 계약의 재검증·운영 부담 때문에 채택하지 않는다. typed Parquet는 교환·분석용이며 원본을 대체하지 않는다.

Catalog는 SQLite 단일 기록 경로, 실행 증거는 불변 JSON이다. 배치의 원자적 게시와 실패 복구를 위한 실행 잠금을 사용한다. 불명확한 출처키나 이름/주소를 자동 동일성으로 승격하지 않는다. 다른 배치 소속과 같은 파일 콘텐츠는 구분한다.

M1 대표는 MOLIT XML, 통계 XLSX, 공시가격 대용량 CSV, NEIS JSON이다. 다른 형식은 목록/한계만 보존한다. baseline 확보 뒤 사용자가 목표를 확정하기 전에는 M1 완료를 선언하지 않는다. Snowflake 계정·예산과 Docker Linux 엔진 준비는 후속 게이트이며 자동 수집·업로드·추천 연결을 암묵적으로 허용하지 않는다.

Airflow와 dbt의 의존성은 별도 Linux 실행 환경에 격리하고 Airflow 운영 DB는 PostgreSQL로 한다. 업무 Catalog와 Airflow 상태 DB를 혼합하지 않는다. 검수된 Parquet의 배치 COPY, 자체 적재원장, dbt 무결성 검사, Query ID/지연 비용 보충을 후속 구현의 기준으로 삼는다.
