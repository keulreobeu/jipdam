# ADR-023 — 개인 할당 GMS 키별 정책과 자동 사용 원장

Status: Accepted. 날짜: 2026-10-21. 근거: 사용자 개인별 키 관리·매 사용 자동 사용량/내역 관리 요청. 관련: GMS-BUDGET-001, TASK-AUDIT-GMS-001.

Windows 사용자별 기존 암호화 보관함을 유지한다. 선택한 키의 비가역 식별값은 로컬 DB 내부에서만 비교하고 외부에는 불투명 account ID를 사용한다. 동일 키를 다른 별칭으로 등록해도 같은 원장/정책을 사용하며, 같은 credential ID의 키 교체는 새 비활성 정책으로 시작한다. 선택은 명시 동작이며 별칭·폴더에서 소유자를 추측하지 않는다. 사용자가 입력하는 관리 이름은 표시용이고 인증/사용자 격리 수단이 아니다. 다른 Windows 사용자는 각자의 보관함과 원장을 사용한다.

정책·크레딧/토큰 합계·활성/불확실 예약은 키별로 계산한다. 카운트와 생성 전에 예약하고 호출 후 수치/상태/Task/모델/시각/실사용/요율 비용/관측 차감을 자동 기록한다. 잔액 조회도 해당 키의 스냅샷으로 남긴다. 같은 개인 키를 다른 앱에서 사용한 차감은 관측 차이이며 이 앱의 실사용 토큰으로 추정하지 않는다. 프롬프트·결과 본문·키는 원장에 저장하지 않는다.

기존 키 미기록 원장은 개인에게 소급 귀속하지 않고 legacy_unattributed로 보존한다. 미확인 과거 예약은 안전하게 귀속할 근거가 없으므로 관리 화면에 표시하고 새 유료 요청을 보류한다. 임의 해제/삭제/초기화하지 않는다. 기존 정책은 선택 키를 재확인/저장해야 키별 정책으로 활성화한다. 스키마 추가는 additive/idempotent이며 이전 calls/model 행을 수정하지 않는다.

현재 최소 보존 1,000·reserve_only·사전 count·만료·최대 예약·기술 상한을 유지한다. 서버 정책 revision과 원자적 예약 검사로 선택 변경/동시 프로세스/재시작에 견적을 재사용하지 못한다. 키별 이력은 로컬 전체 내역 페이지와 요약으로 확인하며 원격 GMS 전체 사용내역 API가 있다고 가정하지 않는다.
