## 목적 및 적용 범위

codex/pipeline-m1-20261029 로컬 기능 브랜치에서 검증한 오프라인 pipeline CLI 계약과 다음 세션 재개 방법. main 반영·원격 배포·전체 M1 완료를 뜻하지 않는다.

## 증상 또는 사용 상황

66개 메타데이터 목록을 Catalog에 등록하고 보존된 XML/XLSX/공시가격 CSV/학교 JSON을 별도 분석 결과로 처리할 때 사용한다.

## 원인과 미확인 사항

등록 항목·논리 데이터셋·파일·배치를 분리하고, Python 정규화와 후속 dbt 분석의 책임을 구분한다. Snowflake 계정/예산과 Linux 실행 준비는 후속 조건이다.

## 실행 절차

제품 폴더에서 pip install -e .[pipeline] 후 python -m budongi.cli pipeline --help를 읽는다. catalog import → inventory → plan → run → status/lineage → benchmark/report 순서로 사용한다. 자세한 명시 JSON 계약은 저장소 docs/pipeline.md에 있다. 다음 채팅은 docs/tasks/pipeline-m1.md와 docs/plans/pipeline-m1.md를 읽고 Jira KAN-28을 이어 사용한다.

## 주의사항 및 예외

실제 원본·DB·키·실행 요청은 Git/LLM에 넣지 않는다. 새 수집·좌표·매칭·추천 연결·원격 업로드는 이 CLI 승인에 포함하지 않는다. 성능 목표는 기준선 뒤 사용자 확정 전 pending이며 M1 완료로 표시하지 않는다.

## 검증 방법 및 결과

현재 파이프라인 계약 테스트 17개 통과: 반복·정확한 원/Decimal·통계 1:N·실패 비게시·영수증 변조·잠금·살아 있는 worker·지연 worker 취소·CLI 종료 코드. Windows 링크 생성 권한이 없어 경로 이탈 시험의 OS 링크 판정은 모의했다. 전체 제품 환경 검증과 최종 실제 기준선은 Task에서 별도 추적한다.
