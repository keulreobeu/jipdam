## 목적 및 적용 범위

집담 로컬 작업본과 codex/git-lifecycle-kan29 미병합 기능 브랜치의 Git 단계 저장 절차다. 메인은 구현과 snapshot 확정을 맡고 전담 서브에이전트가 격리 publisher에서 commit/push한다. main 반영이나 배포 완료를 뜻하지 않는다.

## 증상 또는 사용 상황

Codex 또는 Claude가 구현·수정 작업을 시작하거나 의미 있는 단계 저장, 최종 검증, 원격 저장 실패 복구를 진행할 때 사용한다. 단순 질문이나 읽기 전용 검토에는 빈 branch/commit을 만들지 않는다.

## 원인과 미확인 사항

기존 managed task는 고정 base_commit에서 최종 로컬 커밋하는 계약으로 중간 커밋 후 재검증이 차단된다. 별도 GitLifecycle과 immutable bytes snapshot, common directory 잠금으로 원본 편집과 Git 쓰기를 분리했다. 역할 등록은 보안 인증이나 OS 격리를 제공하지 않는다.

## 실행 절차

Jira/Task/exact scope를 정하고 전담 gstack_committer를 배정한다. 현재 세션에 새 역할이 없으면 같은 책임의 worker를 쓴다. python -m harness git start --request PATH로 origin/main 기반 branch를 만들고, 메인은 snapshot --task ID --stage NAME을 실행한다. 서브에이전트가 반환 snapshot ID로 checkpoint하고 원격 SHA를 읽어 보고한다. verify는 publisher 코드로 테스트한다. reviewed_merge는 필수 위키 확인 후 prepare-finish와 GitHub connector PR/CI/조건부 merge, 실제 read-back receipt를 사용한다. main이 앞서가면 refresh-base 후 재검증한다. 현재 전달은 branch_only이므로 branch를 남긴다.

## 주의사항 및 예외

원본 index와 다른 작업 변경을 포함하지 않는다. 키·DB/raw/runtime을 전송하지 않고 scope/history·hook 변경을 검사한다. push 실패는 같은 snapshot으로 대사 후 재시도한다. 충돌은 자동 해결하지 않는다. refresh 후 새 snapshot은 source HEAD에 새 main이 포함되어야 한다. branch 정리는 실제 병합과 추가 commit/dirty/ignored 산출물 검토 뒤 별도로 수행하며 강제 삭제하지 않는다. agent가 꺼져 있을 때 동작하는 daemon은 설치하지 않았다. 실제 GitHub main 병합/삭제는 이번 branch_only 전달에서 시험하지 않았다.
