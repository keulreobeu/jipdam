# 팀원 위키 작성과 권한 요청

집담 작업자는 모두 [같은 개발 위키](https://kwulreobeu.atlassian.net/wiki/spaces/~7120201d82685826914674999dcbf004921921/pages/360449)에
검증된 사용법·운영·문제 해결 지식을 기록한다. 개인별 중복 위키를 만들지 않고 기존 ID와 문서를 먼저 검색한다.
정책과 실행 방법은 [자동 관리 운영](AUTOMATION.md)을 따른다.

## 팀원의 첫 실행

각자 자신의 Atlassian 계정으로 대상 링크를 열고 보기·작성·편집 가능 여부를 확인한다.
Codex는 본인의 연결 Atlassian을, Claude Code는 공식 MCP의 본인 OAuth를 사용한다.
다른 사람의 세션·토큰·API 키를 공유하거나 저장소에 넣지 않는다.
connection.json은 공유 대상 설정이며 권한을 부여하는 파일이 아니다.

저장소를 새로 받은 팀원은 공유 `pages/`의 문서 ID·revision·본문 무결성·근거를 확인하여
로컬 목록을 자동 복원한다. 실행 DB를 서로 복사하지 않아도 기존 ID를 이어서 사용한다.
본문이 수동 변경되어 검수 기록과 다르면 자동 ACTIVE로 복원하지 않고 검토 대기로 둔다.
원격 binding 이력이 없는 첫 갱신은 같은 ID의 Confluence 문서를 실제로 조회하고 내용·버전·
수동 변경을 검토한 후 snapshotToken으로 수행한다. 원격 문서를 못 읽으면 새로 만들지 않는다.

작업 에이전트는 작업 검증 후 Jira 완료 전에 위키 판단을 수행한다. 작성자는 실제 지정 소유자를
기록하고 고위험 게시·폐기·대량병합의 승인권자를 추정하지 않는다.

## 접근 또는 편집 권한이 없을 때

권한 오류·접근 불가·편집 거부를 확인하면 agent는 사용자에게 다음을 안내한다.

1. 권한이 필요한 대상 페이지·공간 링크와 현재 실패한 동작(보기/작성/편집)을 표시한다.
2. Confluence에 접근 요청 기능이 표시되면 그 기능을 사용하거나 공간 관리자에게 권한을 요청하도록 안내한다.
3. 기존 문서 검색과 갱신에 필요한 보기·페이지 작성·편집 권한을 요청한다. 공간 관리자 권한을 기본 요청하지 않는다.
4. 초안은 로컬에 DRAFT로 보관하고 게시 요청은 SYNC_PENDING으로 남긴다. 접근 실패를 검색 결과 0건으로 간주하지 않는다.
5. 권한이 부여되면 같은 문서 ID·이벤트에서 실제 권한을 재확인하고 중복 생성 없이 동기화를 재개한다.

요청 문구 예시:

> 집담 개발 위키에 작업 중 확인한 검증된 지식을 기록하려고 합니다. 아래 공간/페이지의 보기 및
> 페이지 작성·편집 권한을 요청합니다. 현재 [보기/작성/편집] 단계에서 권한 오류가 발생했습니다.
> 대상: https://kwulreobeu.atlassian.net/wiki/spaces/~7120201d82685826914674999dcbf004921921/pages/360449
> 요청 계정: 본인의 Atlassian 계정

이 문구는 요청 안내이며 자동 발송이나 관리자 권한 변경을 수행하지 않는다. 권한 부여 완료는
실제 조회·편집 성공으로 확인한다. 필수 문서 게시가 막히면 Task/Jira를 미완료 상태로 유지한다.
일반 문서의 동기화 완료 예외도 명시된 승인 정책이 없으면 임의로 허용하지 않는다.
