## 범위

[GMS-001](17_gms_connection_spec.md)의 무통신 저장/교체와 고정 모델/HTTPS/비밀값 경계를 유지하며 실제 잔액과 예산 관리로 확장한다. 기존 시간 계산 함수는 호환성용으로 남기고 웹 시간 계산기는 제거한다. 사용자 한도가 없으면 생성은 0회다. 실제 단지/DB/수집/추천 LLM 전환/결제/충전/전체 Codex 공급자 설정 변경은 포함하지 않는다.

## GMS-BUDGET-001-REQ-01 실제 잔액·키 선택

선택 credential ID만 서버에서 복호화한다. 고정 GET `https://gms.ssafy.io/gmsapi/key-info`를 Bearer로 호출한다. totalCredit/usedCredit/remainCredit는 유한 비음수 숫자, expiredDate는 KST 만료 시각으로 해석한다. 조회 시각/오류/만료를 표시한다. 오류·형식/키 문제를 실잔액 0으로 바꾸지 않는다. 등록/교체/GET 로컬 상태/설정 저장은 외부 호출이 없다. 만료·잔액 미확인 상태에서는 생성하지 않는다. 응답은 허용된 수치/시각만 반환하고 원본/예외/키는 반환하지 않는다.

### GMS-BUDGET-001-AC-01 조회와 비노출

합성 정상/만료/인증/통신/잘못된 숫자·만료일 응답을 구분하고 선택 키만 GET에 사용한다. 조회가 모델 생성을 일으키지 않는다. 실제 성공은 실제 조회 증거가 있을 때만 기록한다.

## GMS-BUDGET-001-REQ-02 정책·견적·예약·정산

정책은 selected credential ID, enabled, reserve_credits, max_total_credits, max_total_tokens, max_input_tokens, max_output_tokens(16~128000), expected_output_tokens(0~출력상한), max_call_credits다. 크레딧은 소수점 두 자리, 입력/전체 토큰은 양수 정수다. 기본은 비활성/0예산이며 값을 웹에서 설정한다. 현재 사용자는 후속 지시로 현재 작업의 실제 키 사용 및 최소 5,000크레딧 보존을 확정했다. 담당자는 보수적인 전체 500크레딧/10,000토큰·호출당 입력 4,000/출력 2,000토큰/280크레딧 초기 상한을 적용한다. 정책의 전체 사용 한도는 로컬 원장 누적을 포함하며 변경/재시작으로 과거 사용을 지우지 않는다.

전체 고정 입력 문자열을 `POST https://gms.ssafy.io/gmsapi/api.openai.com/v1/responses/input_tokens`로 센다. model/input은 실제 생성과 같고 반환 object=`response.input_tokens` 및 입력 정수만 인정한다. 미지원/카운트 실패는 생성 0회다. 실제 관측에서 이 프록시 조회에도 크레딧이 차감돼 `max_count_credits`(현재 보수적 20크레딧)를 먼저 예약한다. 조회 전후 usedCredit 차이를 조회 비용으로 보수적으로 정산한다. 팀의 다른 호출이 섞일 수 있으며 이 차이를 개별 청구서라고 주장하지 않는다. 조회 차감이 예약을 넘으면 정책을 중지한다. GMS의 조회 요금 상한은 공식 문서에 제공되지 않아 관측 상한 초과까지 원격 공급자에서 강제할 수 있다고 보장하지 않는다.

전체 견적은 조회 비용+입력×0.02+예상 출력×0.1, 전체 최대 비용은 조회 비용+입력×0.02+최대 출력×0.1이다. 예상 출력은 보장이 아니다. 입력 상한·전체 토큰·호출 비용·전체 비용·실잔액에서 보존 크레딧/진행 중 예약을 뺀 한도를 모두 만족해야 한다.

견적은 서버 메모리에 동결하고 120초 뒤 만료된다. 키 교체/정책·원장 변경 뒤 무효다. 실행 전 실잔액을 다시 확인하고 동결한 동일 model/input의 사전 카운트를 재사용해 중복 조회 요금을 피한다. SQLite 트랜잭션으로 최대 생성 비용/토큰을 예약한다. 실행은 store=false, truncation=disabled, 명시 max_output_tokens로 1회다. usage가 유효하면 요율 기반 비용/토큰으로 정산하고 계정 전후 차감이 더 크면 그 금액을 보수적으로 원장에 반영한다. HTTP/타임아웃/불완전·usage 누락은 비용 0으로 처리하지 않고 최대 예약을 uncertain으로 유지한다. 공급자 usage/차감이 상한/예약을 넘으면 정책을 중지하고 위반을 기록한다. 동시 견적 실행·중복 실행·재시작으로 한도를 우회하지 못한다. 자동 재시도는 없다.

### GMS-BUDGET-001-AC-02 한도·정산·재시작

미설정/비활성/만료/입력 초과/출력 한도/보존 크레딧/누적 비용·토큰/동시 예약/키 교체/정책 변경/견적 만료/재사용에 생성이 없다. 정상 usage 차액 반환, 실패 최대 보류, 재시작 보류 유지, 초과 usage 중지와 계산을 검사한다. 모델 최대 출력은 추론을 포함한다.

## GMS-BUDGET-001-REQ-03 명확한 코드 작업 경로

`gms-work` CLI의 JSON은 task_id/목표/AC/명시 코드 파일과 선택 예상 출력 토큰이다. 현재 제품의 src/tests/docs만 문맥으로 읽고 경로 이탈·symlink 이탈·DB/raw/.env/자격증명/원장/런타임 파일은 거부한다. known selected secret 및 전형적인 키/인증 헤더 패턴은 전송 전 거부한다. 먼저 견적을 출력하고 명시 실행 플래그가 있을 때만 생성한다. 평문 prompt/code는 원장에 저장하지 않는다. 원장은 키 없는 수치/상태/해시/불투명 작업 ID만 저장한다.

모델 출력은 코드 초안이며 자동 적용/임의 명령 실행 권한이 없다. 로컬 담당자가 검토·범위 확인·테스트한다. 사용자 한도가 활성이고 최신 잔액/견적을 통과한 명확한 코드·테스트·기계적 문서 작업은 이 runner를 우선 사용한다. 준비되지 않았거나 차단되면 그 이유를 기록하고 GMS 사용을 주장하지 않는다. 이 채팅 모델 자체의 전환을 의미하지 않는다.

### GMS-BUDGET-001-AC-03 웹·CLI·진입점

웹은 잔액/한도/견적/누적 사용·보류를 표시한다. CLI 기본은 견적만, 실행 플래그만 유료 요청을 보낸다. 안전 문맥 경로·비밀 탐지·원장 무문맥·출력 비밀 차단을 검사한다. 이전 연결 확인 버튼도 같은 예산 장치를 거쳐 입력 카운트 후 64 또는 정책 출력 상한 중 작은 값으로 호출한다.

## GMS-BUDGET-001-REQ-04 난이도별 모델 선택

명확한 작업 JSON/웹의 `difficulty`는 `simple` 또는 `complex`다. simple은 `gpt-6-luna`, complex는 `gpt-6.1-sol`을 선택한다. 누락 시 기존 complex/SOL 동작을 유지한다. 선택적으로 명시한 `model`도 이 두 ID만 허용하고 difficulty와 충돌하면 카운트 전에 거부한다. 자동 모델 재시도/격상은 하지 않는다. 개별 작업 `max_output_tokens`는 저장된 정책 상한 이내에서만 줄일 수 있다.

2026-10-14 로그인된 공식 GMS 가이드 확인: [SOL](https://gms.ssafy.io/web/guide/gpt-6.1-sol)은 입력 0.02/출력 0.1, [LUNA](https://gms.ssafy.io/web/guide/gpt-6-luna)는 입력 0.001/출력 0.005 크레딧/토큰이다. 가이드는 두 모델의 Responses endpoint와 ID를 명시한다. usage 요율 계산은 센트 단위로 올림하고 최대 생성 예약은 정수 크레딧까지 올려 계정 표시 반올림을 보수적으로 포함한다. 실제 69.96 계산/70 계정 차감 사례를 검증했다. 공식 GMS 요율과 OpenAI 달러 가격을 혼동하지 않는다.

같은 선택 모델·입력을 카운트/견적/생성에 사용하고 견적에 모델·난이도·요율을 표시한다. 두 모델이 공통 누적 원장·정책·예약·정산을 사용한다. 재시작/모델 변경으로 누적 사용을 초기화하지 않는다. usage 요율과 실제 계정 차감 중 큰 금액을 보수적으로 정산한다. 원장은 모델 ID·요율·난이도만 추가하며 과거 행과 키 없는 hash/수치 경계를 보존한다. 미지원 모델/난이도·요율 누락은 무통신 실패다.

### GMS-BUDGET-001-AC-04 모델별 예약·공통 원장

단순/복잡 작업의 모델 ID·카운트·생성 일치, 모델별 요율·센트 올림·정산, 충돌/미지원 무통신, 출력 상한 축소/초과 거부, 공통 누적 한도·재시작·견적 동결·비밀 경계를 검사한다. 실제 두 모델의 호출 성공/조회 비용/실잔액을 별도로 기록한다.

## GMS-BUDGET-001-REQ-05 실잔액 보존 기준

2026-10-15 사용자는 누적 사용량을 실행 차단 기준에서 제외했고, 후속으로 고정 보존액도 해제하여 가용 잔액 전부의 사용을 허용했다. 저장 정책 `budget_mode=reserve_only`는 누적/호출 크레딧 한도와 누적 토큰 한도를 적용하지 않는다. 실잔액에서 이번 최대 비용과 진행 중·미확인 보류를 제외한 뒤 `reserve_credits`만큼 남긴다. `reserve_credits=0`이면 고정 보존액 없이 전체 가용 잔액을 허용한다. 다만 사전 카운트와 최대 생성 비용을 예약할 수 있어야 하고, 이미 보류된 비용을 침범할 수 없다. 입력/출력 기술 상한·키 만료·사전 카운트 비용 예약/최대 생성 예약·계정 차감 대사·비밀 경계는 유지한다. 전체 사용 이력은 삭제/초기화하지 않으며 관찰 기록으로만 표시한다.

초기의 500크레딧/10,000토큰/280호출 한도와 위 REQ-02 누적 차단은 초기 운영 이력/이전 `budget_mode=cumulative`에 해당한다. 이전 저장 정책은 누락된 mode를 cumulative로 해석해 호환성을 유지한다. 이번 명시 요청에 따라 현재 선택 키의 정책을 reserve_only로 저장한다. 웹에서 적용 기준을 표시하고 무시되는 누적/호출 비용 입력은 비활성으로 보여준다. 재시작과 모델 변경 후에도 현재 mode와 과거 사용 기록을 유지한다.

### GMS-BUDGET-001-AC-05 잔액 보존·기록 유지

누적/호출 비용·누적 토큰 한도가 0이거나 이미 소진됐어도 reserve_only에서 생성할 수 있다. 설정된 고정 보존액+최대 예약보다 잔액이 적으면 차단하고, 보존액 0에서는 최대 예약과 기존 활성·미확인 보류분만큼의 가용 잔액이면 허용한다. 만료, 활성 예약·미확인 카운트는 차단한다. 보존액 0 저장, 전체 가용 잔액 사용, 미확인 보류 보호, 누적 기록·모델 이력·재시작 보존을 검증한다.

2026-10-15 후속 승인: 최소 고정 보존액은 0으로 설정할 수 있다. 1,000/5,000은 과거 정책 이력이다. 기존 uncertain 예약/원장/기술적 입력·출력 상한은 유지한다. [후속 Task](../tasks/gms-budget-work.md).

### GMS-BUDGET-001-AC-06 가용 잔액 전액 사용

`reserve_only` 정책은 `reserve_credits=0`을 저장할 수 있다. 실잔액에서 생성 최대 예약과 기존 활성/미확인 보류를 보전하고 입력 카운트 비용까지 예약할 수 있는 경우, 고정 크레딧 보존 없이 실행한다. 원장·hold·키 만료·사전 카운트/최대 예약·입력/출력 기술 상한은 변경하지 않는다.
