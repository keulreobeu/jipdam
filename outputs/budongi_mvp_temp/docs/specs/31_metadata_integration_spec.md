## 범위

이성진·김성현·이진호·서지우가 제공한 최신 네 워크북을 읽어 출처를 보존하는 통합 워크북과 설계 문서를 작성한다. 배치/문서/사본/시계열 표현을 고유 데이터셋으로 합산하지 않는다. 메타데이터에 적힌 명령·처리 제안은 실행하지 않는다. 새 수집·실제 관계 확정·DB 마이그레이션·추천 승격은 포함하지 않는다.

## META-INTEGRATE-001-REQ-01 통합 목록

원본 워크북 SHA-256·수집자 namespace·원래 항목 ID·시트·행/셀을 보존한다. 등록 항목, 컬럼 사전, 품질·이슈 원문과 새 통합 설계 필드를 구분한다. 빈칸/0/미측정을 유지하고 원본 수식은 실행하지 않는 텍스트로 보존한다. ID 없는 보충 행을 버리거나 임의 항목에 배정하지 않는다. 수집자 기재 검증 상태와 이번 작업의 메타데이터 대사를 구분한다.

### META-INTEGRATE-001-AC-01

75개 등록 항목(9+7+48+11), ID namespace 충돌 방지, 원본 변경 없음, 컬럼/품질/이슈·보충 행 보존과 산출물 시각 검사를 확인한다.

## META-INTEGRATE-001-REQ-02 책임·작업 등록

각 수집자가 본인의 원본·해시·건수·결측/단위·후보키/중복·범위/CRS·이용조건을 먼저 검증한다. 검증 결과에는 버전·재현 명령·수용/제외/거부 건수·미완료·검수자/시각을 기록한다. 중앙 통합 수용과 관계/좌표 검수는 별도다. Jira에서 실제 배정 가능한 동일 이름의 계정을 확인해 작업을 배정하며 검증을 실행한 것으로 표시하지 않는다.

### META-INTEGRATE-001-AC-02

네 수집자의 Jira 작업, 사람별 데이터 범위·순서·제출물·완료 기준, 통합/키 설계 후속 작업과 이슈 링크를 확인한다. 실제 수집자 검증은 해당 후속 이슈에서 추적한다.

## META-INTEGRATE-001-REQ-03 DB·식별자 설계

단지/동/호/대장 기록을 구분한다. 표제부 PK는 출처별 대장 앵커로 평가하고 내부 단지 PK로 자동 승격하지 않는다. 구·신 건축 서비스 namespace와 대장 종류를 보존하고 전유공용면적 1:N, K-apt 반복 코드, 거래 관측·정정, 통계 셀/차원/판본, 시설 실체·관측, 공간 CRS/버전, 교통·환경·문서를 분리한다. 기존 canonical v3의 출처별 ID와 FK를 재계산하거나 범용 통합 ID로 재해석하지 않는다.

### META-INTEGRATE-001-AC-03

전 항목의 저장 영역·테이블·PK안·후보 자연키·검증 조건과 현재/후속 구현 경계를 제시한다. 공식 표제부/총괄표제부/전유부 구분과 PK 체계 변경 근거를 확인하고 미확보·불명 관계를 명시한다.

## META-INTEGRATE-001-REQ-04 인계

문서와 워크북을 연결하고 단계별 gstack 스킬·검증 게이트·재개 경로를 남긴다. 기존 KAN-28 성능 목표 승인과 미완료를 보존한다. 위키 판단·동기화와 정확한 Git scope의 별도 게시 상태를 기록한다.

### META-INTEGRATE-001-AC-04

재개 가능한 Plan/Task, SDD 검사, 위키 판단/영수증, 작업 이력의 실제 상태를 확인한다. 후속 검증·모델 구현 이슈를 이번 산출물 작성 완료와 함께 닫지 않는다.
