## 목표·현재 상태·범위

로컬 집담 앱에서 국토교통부·Kakao Local·서울 열린데이터광장 등 여러 API 자격증명을 등록하고 구분한다. CRED-001 요구사항은 **approved**이며, Windows loopback 설정 화면·HTTP API·암호화 저장소가 구현됐다. [제품 Task](../tasks/api-credential-vault.md)는 구현을 추적하며, 2026-10-07 현재 Windows 사용자 세션에서 합성 키의 OS Credential Manager 저장·읽기·삭제 왕복을 검증했다. 비대화형 자동 실행 세션에서는 OS 저장소가 없을 수 있어 fail-closed하며 평문 fallback을 하지 않는다. 제품 검증 상태와 문서 적용 Task는 각각 해당 Task에서 관리한다.

사용자가 만든 평면 폴더 안에 여러 연결 API 키를 저장한다. 폴더는 사용자가 정한 정리 위치이고, 연결 API는 키가 사용될 연동 대상을 구분한다. 같은 연결 API에 키를 여러 개 저장할 수 있고 각 키에는 사용자가 정한 별칭이 있다. 각 키는 폴더 ID·공급자 ID·불투명한 자격증명 ID로 참조한다. 별칭은 표시용이지 인증값이나 파일 경로가 아니다.

보관함은 추천·임대차 데이터베이스와 분리된 로컬 전용 저장소다. Windows MVP에서는 사용자 프로필의 `%LOCALAPPDATA%\\Jipdam\\credentials.sqlite3`에 메타데이터와 암호문을 저장하고, AES 키는 `Jipdam/ApiCredentialVault/MasterKey/v1` 이름의 generic credential로 해당 Windows 사용자 계정의 **Windows Credential Manager**에 둔다. API 키 값은 저장 전에 AES-256-GCM으로 암호화하며 인증 태그 검증에 실패한 값은 사용하지 않는다. 운영체제 자격 증명 저장소를 사용할 수 없거나 안전한 백엔드가 확인되지 않으면 저장·복호화·외부 호출을 실패 처리하고 평문 파일·SQLite·환경변수로 대체하지 않는다.

현재 역사 데이터 스크립트의 환경변수 계약은 유지한다. 이 보관함은 신규 전월세 공급자 어댑터가 사용할 TARGET다. 실제 전월세·시설 API 호출은 [실데이터 Task](../tasks/rental-real-data.md)의 별도 보류가 풀릴 때까지 하지 않는다. 키 등록·수정·삭제는 외부 API 요청이나 유료 쿼터 활성화를 일으키지 않는다.

## CRED-001-REQ-01 폴더·키 등록·별칭

- 폴더는 한 단계 분류용 이름으로 만든다. 각 폴더에 서로 다른 공급자와 같은 공급자의 API 키를 여러 개 둘 수 있다.
- 각 키는 공급자 식별자, 사용자가 정한 별칭, 폴더 ID, 암호화된 자격증명 값, 생성·갱신 시각, 암호화 형식 버전을 가진다. 폴더명·별칭·공급자 식별자는 비밀값이 아니다.
- 폴더·키 생성, 연결 API 변경, 별칭 수정, 키 교체, 키 삭제, 폴더 목록 조회를 제공한다. 연결 API는 신규·수정 화면 모두 지원 목록에서 선택한다. 제공자를 바꾸면 기존 키를 서버에서 잠시 복호화해 새 제공자 ID에 바인딩되도록 다시 암호화하며 키 원문은 반환하거나 기록하지 않는다. 저장 후 화면은 별칭·연결 API·폴더만 표시하고 키 값은 마스킹한다. 기존 키 값을 다시 읽어 보여주지 않는다.
- 목록·HTTP 응답에는 암호문도 포함하지 않는다. 실제 공급자 호출 설정은 자격증명 ID를 지정하며, 공급자 선택을 이름 문자열로 추측하지 않는다.
- 등록할 키가 해당 폴더명·별칭에 포함되거나, 교체 시 이전/새 키가 별칭에 포함되면 입력 오류로 거부한다. 메타데이터는 용도만 입력한다. 잘못된 Unicode 이름도 입력 오류로 처리한다.

### CRED-001-AC-01 여러 키·별칭·영속성

같은 연결 API에 속한 여러 자격증명이 서로 다른 ID와 별칭으로 저장·조회된다. 앱 재시작 후에도 폴더와 별칭이 유지되고 목록·로그·응답에는 원 키 값이 나타나지 않는다. 키 교체와 연결 API 변경은 지정한 자격증명 한 건만 변경한다. 연결 API 변경 뒤 원래 키 값은 새 연결 대상 ID로만 복호화할 수 있다.

## CRED-001-REQ-02 암호화와 접근 경계

- API 키 원문은 암호문으로 변환한 뒤에만 저장한다. 암호화 키는 DB·프로젝트 폴더·저장소와 분리해 Windows Credential Manager에서 사용자 계정 범위로 관리한다.
- 로컬 서버만 키를 복호화해 선택된 공급자 어댑터의 메모리에서 사용한다. 키를 HTML/JavaScript 상수, URL, 브라우저 localStorage/sessionStorage, LLM 입력, 추천 Tool 입력, 로그, 예외·오류 응답, 원장·스냅샷에 넣지 않는다. 등록·교체 요청의 HTTP 본문은 서버로 한 번 전달하고 원문을 응답으로 돌려주지 않는다.
- 앱은 loopback 주소에만 바인딩한다. 자격증명 변경 요청은 로컬 Origin을 확인하고, 외부 배포·원격 관리·공유 동기화는 지원하지 않는다.
- CURRENT HTTP 서버는 요청을 독립적으로 처리하고 연결 읽기에 5초 비활성 타임아웃을 둔다. 불완전한 본문은 거부하며 미지원 메서드·파싱 오류에도 입력을 반사하지 않는 JSON과 no-store·보안 헤더를 사용한다. 비 ASCII CSRF는 403으로 거부한다. 수정 창은 저장·버튼 취소·Escape 등 모든 닫기 경로에서 키 입력을 비운다.
- Windows 계정·Credential Manager 상태가 달라 복호화할 수 없으면 자격증명을 사용할 수 없음을 표시하고 새 키 입력을 안내한다. 자동 평문 복구 경로는 만들지 않는다.

### CRED-001-AC-02 암호문 저장·복호화 실패

저장소 파일에는 키 원문이 없고, 원래 계정의 OS 자격 증명 저장소와 유효한 인증 태그가 모두 있어야 복호화된다. OS 키 저장소 없음·잠김·권한 오류·잘못된 태그에서는 fail-closed로 처리하며 평문 대체 저장·외부 요청은 발생하지 않는다.

### CRED-001-AC-03 비밀값 비노출

키를 추가·교체한 후 목록·브라우저 저장소·응답·서버 로그·오류 응답·LLM 입력을 검사해 원문이 없는지 확인한다. 공급자 어댑터의 요청만 선택된 키를 사용하며 키 ID와 별칭은 호출 결과 로그에서 원문과 분리된다.

## CRED-001-REQ-03 폴더 삭제와 연쇄 삭제

폴더 삭제 전에 폴더명과 포함된 키 개수를 보여주고 명시적으로 확인받는다. 확인 후 한 트랜잭션으로 폴더와 모든 키 레코드를 삭제한다. 실패하면 폴더·키 모두 유지한다. 성공 후 해당 폴더의 자격증명 ID는 선택·복호화할 수 없고 고아 키 레코드가 남지 않는다. 이 동작은 앱 보관함에서의 논리적 영구 삭제를 뜻하며 SQLite/WAL·운영체제 백업 매체의 물리적 흔적까지 지웠다고 주장하지 않는다.

CURRENT HTTP 삭제 요청은 `confirm: true`와 화면에서 확인한 `credential_ids` 배열을 함께 보낸다. 배열이 없으면 400, 삭제 트랜잭션에서 현재 키 ID 목록과 다르면 409로 거부하고 화면을 새로 조회한 뒤 재확인한다. 폴더 개수와 키 목록은 같은 읽기 스냅샷에서 조회한다. 서버 내부 Python 삭제 함수의 기존 명시적 확인 계약은 유지하며 HTTP 경로에는 목록 대조를 필수 적용한다.

### CRED-001-AC-04 폴더 삭제 cascade

폴더에 0개·1개·여러 키가 있을 때 확인 취소는 아무것도 삭제하지 않는다. 확인한 삭제는 폴더와 모든 하위 키를 원자적으로 제거하고 연결 자격증명의 이후 조회는 실패한다. 강제 DB 오류에서는 전체 롤백되고 고아 레코드가 생기지 않는다.

## CRED-001-REQ-04 공급자 사용과 설정 화면

보관함 설정 화면은 폴더와 별칭을 만들고 키를 추가·교체·삭제한다. 신규 전월세 adapter는 명시적으로 설정된 credential ID에 대응하는 공급자 키만 서버에서 불러온다. 저장·별칭 수정·폴더 삭제 자체는 API 요청을 일으키지 않는다. 키 등록과 외부 API 호출은 별도 동작이며, 실제 호출은 보류 해제와 해당 공급자의 이용조건·쿼터 검토 후 허용한다. 유료 쿼터·결제 기능은 자동 활성화하거나 자동으로 초과 사용하지 않는다.

### CRED-001-AC-05 저장 동작의 무통신·사용자 선택

키 등록·교체·삭제·폴더 삭제 때 외부 호스트 요청이 없다. 공급자 요청은 설정된 자격증명 ID와 일치하는 서버 adapter에서만 발생하며, 보류 상태나 호출 불가 상태에서는 네트워크 요청 없이 이유를 표시한다.

## CRED-001-REQ-05 SDD·제품 상태

이 보관함은 전월세 웹 비교와 연계하는 신규 제품 기능이다. 문서·설계 Task 완료는 보관함 구현·API 사용·데이터 수집 완료를 뜻하지 않는다. 사용자 승인 없이 실제 API 호출, 사용료 설정, 키 공유·동기화, 폴더 삭제를 수행하지 않는다.

### CRED-001-AC-06 문서·Task·추적 연결

Spec, ADR, Plan, Task, runtime·데이터 계약, 개발 규칙과 루트 SDD 원장이 같은 보관·암호화·삭제·보류 계약을 가리킨다. 제품 Task는 실제 구현·검증 상태를 기록하고 실행하지 않은 제품 AC는 `not_run`으로 남긴다. 구현 후 검증·수정은 [TASK-CRED-QA-001](../tasks/credential-vault-qa.md)에서 별도로 추적한다.

## 검증 계획·미결정

구현 Task는 합성 키로 다중 공급자·별칭·폴더·재시작·암호화 검증을 수행한다. 테스트에서만 OS Credential Manager adapter를 주입할 수 있지만 제품 실행 경로는 실제 보안 저장소 없이는 fail-closed여야 한다. 폴더 삭제 취소·성공·DB 오류 롤백, 고아 레코드, 암호문 tamper, OS 계정/키 저장소 접근 실패, secret redaction, 외부 네트워크 미호출을 검증한다.

제품 AC-01~05는 구현된 테스트로 검증한다. AC-02의 AES-GCM·fail-closed 동작은 합성 테스트로, Windows Credential Manager의 합성 master-key 영속 round-trip은 현재 Windows 사용자 세션에서 `test_native_credential_manager_round_trip_uses_synthetic_key`로 2026-10-07 확인했다. 문서 적용 AC-06은 [문서 Task](../tasks/credential-vault-sdd.md#doc-validation)에서 검증한다.
